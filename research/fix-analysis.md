# 修好回测和策略 — 第一性原理分析

## 一、策略在干什么 (第一性原理)

预测市场交易的原子逻辑只有一句话:

> **当且仅当 P_model(outcome) − P_market(outcome) > 成本时下注**

一切复杂性都来自三个估计问题:
1. **P_model 准不准?** (预报校准)
2. **P_market 偏不偏?** (市场偏差)
3. **回测能不能测出 1 和 2 的真相?** (验证有效性)

pm-bot 的策略框架 (EMOS 校准 + edge 过滤 + Kelly + 熔断) 在第 1、2 点上是对的。
它的回测在第 3 点上是错的 — 而第 3 点错了,1 和 2 的结论全都不可信。

## 二、回测的三个原罪 (已实证)

### 原罪 1: 循环结算 (最致命)
```python
# run_weather_backtest.py:283
won = rng.random() < signal.bucket.true_prob
# 其中 true_prob = 落在桶里的 ensemble 成员比例 (line 194)
```
模型 (EMOS) 和"真相" (成员比例) 来自**同一组** ensemble 成员。
回测回答的不是"模型能不能预测真实温度",而是"EMOS 能不能预测成员分布"。
证伪实验 (`research/honest_resolve.py`): 改按 `true_temp` 结算 → 136 笔 0 胜, −72%。

**第一性原理**: 验证概率预报的唯一合法标尺是**实现值** (realization)。
用预报分布自身去验证预报,等于用尺子量尺子。

### 原罪 2: DGP 时间顺序颠倒
v1 先抽 `true_temp`,再以它为中心抽成员。这意味着**成员几乎完全揭示实现**
(31 个成员,σ≈2 → 后验 σ≈0.36)。真实世界的时间顺序是反的:
**先有预报 → 后有实现**。实现是从"以预报为条件的真分布"里抽出来的。

v2 修正:
```
1. f_mean ~ 季节模型 + N(0,3)        # 预报员的最佳猜测 (先存在)
2. members = 31 × N(f_mean, 1.5)      # 集合离散度
3. true_temp ~ N(f_mean, σ_emos_city) # 实现 ~ 真实预报误差 (后存在)
```
只有这个顺序下,"模型是否校准良好"才是个有意义的问题。

### 原罪 3: 把结论写进假设
`tail_underprice_factor = 0.7` — 市场低估尾部 30% 是**写死的**。
回测验证的是"假设成立时策略能执行",不是"假设成立"。
诚实的做法: 把 bias 做成扫参,报告 breakeven 点 (v2 做法),
然后用**真实历史盘口**去测量 bias 到底是多少 (replay,见第五节)。

## 三、v2 诚实回测的结论

`research/backtest_v2.py` (DGP 已修正,对实现结算,固定阈值如 NY ≥35°C):

| 市场尾部 bias | 交易数 | 胜率 | 收益 |
|---|---|---|---|
| 0.50 (低估50%) | 72 | 0% | −48% |
| 0.70 (低估30%) | 58 | 0% | −42% |
| 0.85 | 54 | 0% | −40% |
| 1.00 (无低估) | 53 | 0% | −39% |

**注意**: 这个 v2 版本仍有阈值设定问题 (固定 X=clim_max−3 导致机会极少且模型
触发逻辑与阈值错位)。它最大的价值是否定性的: **证明了 v1 的 +355% 是人造的**,
而不是给出新的可信收益数字。不要引用 v2 的具体收益数字做决策。

### 真正的教训 (比数字重要)
1. **尾部阈值不能跟着预报跑**。v1 让阈值 = 预报均值+1.2σ,等于在赌"预报误差为大正值",
   天然胜率≈0。真实市场里 X 是固定的 (建市时定死),edge 来自**预报更新后市场没跟上**
   (forecast latency) 或**人群系统性偏差**。
2. **校准良好 ≠ 有 edge**。v2 里模型按构造是校准的,但 bias=1.0 时依然不赚钱。
   校准只是"不亏钱"的必要条件,赚钱需要市场犯错。
3. **小样本是硬伤**。31 个成员估计尾部概率,抽样噪声巨大。Tail 策略的 Kelly
   仓位必须对估计噪声打折扣,否则就是在用噪声下注。

## 四、策略本身要修什么

### 必须修 (机械正确性)
1. **import 已烂**: `pm_bot/core/weather.py` 只有 `bucket_probability_numpy`,
   `emos_edge.py` 引用的 `bucket_probability` / `_get_emos_calibrator` /
   `_last_metar_obs` / `_hours_until_resolution` 都不存在;`STRATEGY_DEFAULTS`
   在 config 里不存在。模块根本 import 不了。
2. **tail plumbing bug**: 主循环过滤掉 tail 桶后再传给 `_tail_strategy`,
   真 tail 桶永远到不了 tail 策略 (之前已发现)。

### 应该改 (第一性原理)
3. **阈值语义**: 策略应该按"固定 X 桶"思考,而不是"预报相对位置"。
   信号逻辑改为: 对每个真实存在的 ≥X°C 桶,算 P_model(X) vs market price。
4. **edge 阈值要覆盖**: 手续费 (2-3%) + 模型估计噪声 + 逆向选择。
   8% 是合理的下限,尾部用 8-10% (与 tradetheoutcome 的公开建议一致)。
5. **只做近端**: arXiv 证据显示偏差随期限衰减,30-48h 窗口 edge 接近 0。
   加 lead_time 过滤: 只做 <24h 的市场。
6. **流动性过滤**: 尾部桶盘口薄,大资金滑点吃掉 edge。小资金 ladder,
   大资金直接放弃或只做 NO 端。
7. **Kelly 打折**: 尾部概率估计噪声大,Kelly 用 0.1 倍是保守且对的,保持。

### 不要碰
- EMOS 校准路线 (真实数据训练,这是差异化)
- station bias 修正 (机场 vs 市区是真实存在的)
- dead-man 熔断框架

## 五、真正验证 edge 的唯一路径: Replay

合成回测永远回答不了"市场真低估了吗"。必须:

1. **历史盘口**: Polymarket CLOB API 有 trade history;gamma-api 有市场元数据。
   取每个天气市场决议前 6h/24h 的 YES/NO 价格。
2. **同期预报**: Open-Meteo archive API 取决议站点的实测序列;
   用 archive 時刻的 ensemble (或 ERA5 + 按实测误差加噪) 重构"当时能拿到的预报"。
3. **真实结算**: 按 Polymarket 当时的决议规则 (weather.gov 小时表) 算出赢家。
4. **复执行**: 信号→按当时盘口深度模拟成交→扣费→结算。

MihirM9 的 polymarket-weather-bot 自带 backtesting/replay 引擎,可参考结构。
这是 DSH worker 下一步最适合干的杂活: 写 replay 数据管道。

## 六、一句话总结

**v1 回测用预报验证预报,用假设验证假设 — 数字全是人造的。
修好的标准只有一条: 结算必须对实现,时间顺序必须先预报后实现,
市场偏差必须当参数扫、不当常数写死。策略框架是对的,缺的是一次诚实的验证。**
